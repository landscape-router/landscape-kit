# `lkit migrate`

将仍在运行的手工部署迁移为同版本的 lkit 受管安装。迁移不升级版本，不修改旧配置
目录；保护 `.lkb` 和事务现场保留用于诊断与人工恢复。

```text
lkit migrate --from <CONFIG_DIR> [--install-dir <PATH>]
             [--repository [<BASE_URL>]] [--yes]
```

迁移入口面向 CLI。旧部署识别及 unit 接管要求 systemd；其他服务后端在修改前拒绝。
目标根不能包含 data、releases、service 或 current，也不能已有 lkit 安装状态。
源目录必须是包含 Landscape 特征文件的真实目录，旧实例必须运行并支持配置导出 API。

前端只读取源目录、运行进程与导出版本，展示源目录、目标根、版本和停止方式并确认。
非交互模式必须显式 `--yes`。拒绝确认不创建事务或备份。提交的结构化操作绑定源目录
身份、PID 与进程启动时刻、二进制与命令行摘要、旧 unit 身份和版本；daemon 在安装锁下
重新校验，源实例被替换或版本变化时拒绝，不能把确认用于另一实例。

操作由 daemon 直接执行，不派生 lkit worker、不读取终端，不接受原始 argv、会话环境
或任意续跑事务 ID。CLI 输出操作 ID 后观察结果；Ctrl+C、SIGHUP 或 SSH 断开只停止
观察。`operation status/list` 查询持久化结果，仅允许取消排队请求。

执行顺序：

1. 校验目标根、源实例和导出版本，创建并关联迁移事务。
2. 创建完整迁移 `.lkb`，包含导出配置、运行二进制和现场 static 内容，验证备份后继续。
3. 停止旧实例。systemd unit 的原件及运行／开机状态在修改前持久化，随后停止、禁用并
   解除旧注册冲突。旧实例为前台进程时，操作提示 PID，等待用户从另一会话手工停止；
   只有验证原进程退出才继续，等待期限沿用启动检查超时，超时失败并保留备份。
4. 从备份重建目标 release 和新 data，写入初始化配置，注册并启动受管 Landscape。
5. 完成启动与稳定健康检查，写入包含本次事务 ID 的安装状态并提交事务。

前台进程不会由 lkit 自动重启；失败时用户可在保留的旧目录中重新启动它。受管旧 unit
按保存的原件、运行状态和开机状态恢复。回滚失败保留 `rolling_back`，由 daemon 重试，
不会把未恢复现场标记为已完成。准备阶段中断不重放备份与迁移；停止或激活阶段中断
恢复旧服务并清理未提交目标；状态已经持久化且事务 ID 匹配时补全提交。

成功返回 `0`，参数错误 `2`，普通失败 `1`，完成回滚 `5`，恢复未完成 `6`；前端退出
观察返回 `130`。提交或恢复均更新原操作结果，daemon 重启不会再次执行已完成迁移。
