# i18n 设计考量

状态：V1 不做 i18n，仅预留抽象接口

## 核心原则：开发者日志与用户消息分离

库层的 `thiserror` 错误信息面向开发者（英文），通过 `tracing` 输出到 stderr。
CLI 层负责将错误转为用户可读信息（中文），输出到终端。

```
库层 (core/client/app):
  thiserror #[error("backup index not found at {path}")]
  → Display → tracing::error! → stderr（英文，给开发者看）

CLI 层:
  anyhow::Error → CliMessages::format(key, params)
  → 终端 stdout/stderr（中文，给用户看）
```

## V1：硬编码中文入口

```rust
// lkit-cli/src/messages.rs

use std::collections::BTreeMap;

pub struct CliMessages;

impl CliMessages {
    /// V1: 硬编码中文。V2: 替换为 fluent/ICU 查表。
    pub fn format(key: &str, params: &BTreeMap<&str, String>) -> String {
        match key {
            "backup.not_found" => format!("备份点 {} 未找到", params.get("id").unwrap_or(&"?".into())),
            "backup.restore.failed" => format!("恢复备份点 {} 失败", params.get("id").unwrap_or(&"?".into())),
            // ...
            _ => format!("未知错误 ({}): 请查看日志获取详情", key),
        }
    }
}
```

调用点：

```rust
// lkit-cli 各命令中
let msg = CliMessages::format("backup.not_found", &{
    let mut m = BTreeMap::new();
    m.insert("id".into(), backup_id.to_string());
    m
});
eprintln!("{}", msg);
```


重构范围：仅 `messages.rs` 一个文件 + 新增 `locales/` 目录存放 FTL 文件。

## 命名约定

消息 key 用小写 + 点号分隔：`{domain}.{variant}`

```
backup.not_found
backup.restore.failed
backup.delete.permission_denied
install.init_file.invalid
upgrade.check.network_error
```

key 由调用者直接写在调用点。不做 enum 或常量统一管理——调用方已经足够明确，多加一层间接反而增加维护负担。

## 不做的

- 不在 V1 引入任何 i18n 依赖（fluent、icu4x、gettext）
- 不在库层（core/client/app）写面向用户的中文字符串
- 不提前搭 FTL 文件——空文件不等于抽象
- 不做消息 key 常量枚举——避免多一层不必要抽象
