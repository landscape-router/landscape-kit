# i18n 设计考量

- 状态：V1 不做 i18n，仅预留抽象接口

## 核心原则：开发者日志与用户消息分离

- 库层 `thiserror` 面向开发者（英文），经 `tracing` 输出到 stderr
- CLI 层负责将错误转为用户可读信息（中文），输出到终端

## V1 入口

- 集中在 `lkit-cli/src/messages.rs`，单一 `CliMessages::format(key, params)` 函数
- V1 硬编码中文，key 用小写点号格式（`backup.not_found`），调用方直接写 key 不做常量枚举
- V2 替换内部实现为 fluent/ICU，不改调用点
- 不在库层写面向用户的中文字符串
