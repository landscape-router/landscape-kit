# 概览与产品边界

## 1. 文档信息

- 状态：Draft
- 项目名：Landscape Kit

## 2. 项目背景

Landscape 当前已经具备完整 API 与文档能力，但缺少一个面向运维、部署与救援场景的独立本机管理工具。目标是新增一个独立仓库，实现：

- 首次安装、自动初始化与基础网络部署
- 升级、手动备份、恢复与失败回滚
- 日常运行管理与故障诊断
- 无网络情况下可用的本机 CLI 管理 / 救援入口
- 可脚本化、可被第三方调用的 CLI 入口

该工具不新增外部 API，而是复用现有 Landscape API，并在本机完成必要的系统操作。V1 的交付优先级以 CLI 可用性为先，交互场景通过引导式 CLI 完成。

## 3. 产品定位

### 3.1 核心定位

本项目是一个 **独立仓库 `landscape-kit`** 的 **本机管理器**，其二进制入口为 **`lkit`**：

- **架构上共享应用层**：非交互 CLI 与引导式 CLI 共用同一套用例层能力
- **产品交付上 CLI 优先**：V1 先解决本机安装、管理与救援入口问题
- **引导式 CLI 是首版主交互方式**：用于人工运维、引导式安装与离线救援
- **保留非交互 CLI 入口**：用于脚本化、自动化、第三方调用

### 3.2 运行位置与路径

首版主要运行在 **Landscape 所在主机（路由器本机）**。

- Landscape HOME 默认路径：`~/.landscape-router`（可通过 `LANDSCAPE_HOME` 环境变量覆盖）
- 管理器工作目录默认路径：`~/.landscape-kit/`（详细发现规则见 [03-lifecycle](./03-lifecycle.md)）

### 3.3 V1 主价值

V1 的核心价值不是单纯的自动化安装器，而是一个在 **无网络或 Web UI 不可用场景下仍可工作的本机 CLI 管理 / 救援入口**，同时覆盖：

- 安装与自动初始化
- 手动备份与恢复
- 更新与失败回滚
- status / logs / restart / diagnose

### 3.4 与 Landscape 的关系

- 管理器通过 **Landscape 现有 API** 获取状态、导出配置、执行管理动作
- 管理器通过 **本机系统能力** 完成安装、升级、重启、备份、恢复等主机侧操作
- 首版不新增外部 API，不设计新的远程控制协议
- 安装阶段所需 release 产物通过多源并发探测获取，支持 GitHub Releases / HTTP 镜像（含 R2）/ 本地路径，自动选最快可用源

## 4. 已确认设计原则

1. **独立仓库**，不直接并入当前 monorepo
2. **非交互 CLI 与引导式 CLI 共用应用层**，业务逻辑统一收敛到应用层
3. **V1 交付优先级以 CLI 为先**，交互场景通过引导式 CLI 完成，优先满足本机安装、管理与救援需求
4. **首版不做守护进程**，管理器是一次性命令程序 / 交互式会话程序
5. **Landscape 不直接 push 控制临时 CLI 进程**，首版采用管理器主动调用 Landscape API + 本机执行系统动作
6. **`landscape_init.toml` 不是常驻运行配置**，仅在首次初始化 / 重初始化时使用，初始化后内容会落到 `landscape.toml` 与 `landscape_db.sqlite`
7. **首版详细网络初始化参数优先通过引导式 CLI 收集**，不在 V1 CLI 暴露大规模 `--wan-*` / `--lan-*` 细粒度参数，非交互安装优先通过 `landscape_init.toml` 驱动
8. **`static/` 是前端运行所需的静态发布资源**，默认纳入备份点与实例恢复范围
9. **Landscape release 通过多源并发探测获取**，支持 GitHub Releases / HTTP 镜像（含 R2）/ 本地路径；`lkit mirror` 子命令负责镜像管理，上游零改动
10. **V1 服务安装方式仅支持 systemd**
11. **landscape_api_token 暂不纳入备份/恢复设计**
12. **降低用户负担**：`lkit` 无参数进入通用启动器，安装/备份/状态等均可从主菜单导航；网络初始化参数通过交互方式收集；自动化场景复用 `landscape_init.toml`

## 5. 非目标（V1 不做）

- 不新增外部 API
- 不做守护进程 / 常驻 agent
- 不做多主机远程统一管理
- 不做全量配置编辑器（V1 不替代 Web UI 的配置能力）

## 6. 目标用户与典型场景

### 6.1 目标用户

- 本机运维人员
- 安装部署人员
- 需要在断网/救援场景下本地操作 Landscape 的用户
- 需要脚本化管理 Landscape 的第三方系统

### 6.2 核心场景

1. 新机器首次部署 Landscape，并通过引导式 CLI 完成基础网络初始化
2. 无网络或 Web UI 不可用时，通过本机 CLI 进行配置/救援
3. 升级前手动或自动创建备份点
4. 升级失败后一键回滚
5. 查看服务状态、日志、健康检查结果
6. 导出当前配置，用于重新部署或迁移
7. 从 GitHub Releases 或指定路径自动获取 release 产物完成安装/升级
