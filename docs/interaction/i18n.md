# 命令行本地化

`lkit` 支持英文与简体中文用户界面。显式覆盖使用以下短代码：

- `en`：英文；
- `zh`：简体中文。

全局参数可以放在子命令前后：

```sh
lkit --lang zh check
lkit check --lang zh
LKIT_LANG=zh lkit check
```

语言选择优先级为 `--lang`、`LKIT_LANG`、配置预设（`/root/.lkit/config.toml` 的
`[ui] language`）、`LC_ALL`、`LC_MESSAGES`、`LANG`、默认英文。空环境变量视为未设置。
`--lang`、`LKIT_LANG` 与配置预设只识别 `en` 与 `zh`；系统 locale 会提取主语言，
因此 `zh_CN.UTF-8` 和 `zh-CN` 都选择中文。

优先级更高的来源一旦存在就决定结果：其值不受支持、无法解析，或系统 locale
的主语言不是 `en`/`zh` 时，静默回退到英文，不产生参数错误。例如，即使
`LANG=zh_CN.UTF-8`，`--lang fr` 仍强制使用英文。

配置预设是**宽容读取**：`config.toml` 缺失、损坏或值不受支持时该来源被跳过，
不影响任何命令；它与 `--lang`/`LKIT_LANG` 一样需要仓库信息无关的解析，不阻断命令。
配置预设固定读取 lkit 地盘（`/root/.lkit/config.toml`），在命令行解析完成后生效，
因此无法覆盖 clap 帮助与参数错误；`--lang` 与 `LKIT_LANG` 可以。参见
[配置文件（`config.toml`）](../deployment/config.md)。

语言选择覆盖 Clap 帮助、检查报告、Ratatui 控制台、交互提示、进度与命令结果。systemd
委托前将最终语言写入内部 worker 环境，前端与 worker 不得混用语言。TUI 和表格按终端显示
宽度对齐中文宽字符。

Ratatui 控制台右下角的语言指示在可切换时显示目标语言（以目标语言自身文字书写，
如英文界面下的 `[L] Switch to 中文 (zh)`），按 `L` 或点击该指示即切换到所示目标；
文本编辑中退回显示当前语言并注明 `L` 暂停（输入时 `l` 是普通字符），退出确认层等其余不可切换状态只显示当前语言。
这个运行时选择覆盖启动控制台时解析的语言，并传递给从控制台启动的后续命令与
systemd worker；不改写进程的 locale 环境变量。切换时会原子写回 `config.toml` 的
`[ui] language`，下次会话沿用该预设；写回保留注释、未知 section/字段与原有顺序，
配置损坏时切换仍生效但显示提示。CLI 命令只读配置预设，`--lang`/`LKIT_LANG` 覆盖
不写回文件。

以下机器契约不翻译：命令名和参数名、枚举参数值、检查 ID、状态键、事务 phase、JSON
字段、服务名、路径、URL、命令示例和退出码。OS、systemd、HTTP 等外部系统返回的原始错误
可以保留原文，`lkit` 自己添加的错误类别和处理建议按选定语言显示。
