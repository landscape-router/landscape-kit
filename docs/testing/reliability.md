# 测试执行与故障诊断

## 执行清单

Rust CI 的 CLI 单元测试由 `scripts/ci/lkit-unit-tests.txt` 指定。清单只纳入已确认
可以在 CI runner 执行的隔离测试；系统服务与网络场景由 fixture 或虚拟机执行。
`scripts/ci/run-test-selection.py` 首先通过 `--list` 获取实际测试名，再校验所有过滤器。
清单为空、重复过滤器、空测试列表或任一过滤器匹配零个测试均导致失败，校验失败时不执行测试。
执行中的任何测试失败均保留非零退出码，不自动重试或忽略失败。

每次运行生成 JSON inventory，记录实际测试总数、各过滤器匹配列表、已选测试数及未选测试名。
未选项不表示已覆盖，也不自动获得在宿主执行的许可；新增模块需要检查清单并明确测试层。
Rust workflow 的 `--lib` 不包含 `lkit` 二进制单元测试。CI 单元清单和 fixture 每个分组都经过
同一个非空校验器，改名或移动测试必须同步更新清单。

本地可使用 `--list-only` 校验清单，只编译并列出测试，不执行全量测试。普通开发仍只运行
当前修改涉及的精确单元模块；fixture 由 CI 执行。

## 失败现场

fixture CI 使用独立的 `LKIT_TEST_WORLD_DIR` 临时根，诊断输出写入
`LKIT_TEST_ARTIFACT_DIR`。断言 panic 时，`TestWorld` 在清理改变现场之前导出快照，
随后继续停止替身进程并删除临时目录。归档失败只记录诊断，不掩盖原始断言失败。

快照包含文件类型与大小、操作和事务的状态字段、事件时间线、检查点及指定日志。
不复制请求正文、自由文本操作消息、配置、密码文件、数据库或备份内容；日志中含密码、
token、PSK、Authorization 等敏感标记的行被替换。符号链接只记录类型，不跟随读取。
文件读取上限 256 KiB、条目上限 2000、递归深度上限 10；损坏记录或超大日志标注为不可读。
日志脱敏基于字段和行标记，fixture 必须继续使用一次性测试凭据，不应注入真实凭据。

CI 的收尾步骤收集未完成析构的剩余 fixture 目录，并上传各分组的诊断和 inventory，保留
7 天。强制取消 runner 或直接终止虚拟机可能来不及执行收尾，不能保证这些情况下必有归档。
导出程序只用于 fixture 二进制，不属于生产 CLI。

## 事务故障矩阵

故障钩子只编译进 `test-support`，生产构建不含暂停或注入错误入口。
`LKIT_TEST_REPAIR_CHECKPOINT` 在指定检查点暂停，测试强杀 daemon 并重新启动；
`LKIT_TEST_FAIL_CHECKPOINT` 在指定边界返回注入的 I/O 错误，走正常失败恢复路径。
后者验证错误传播与恢复，不模拟真实 ENOSPC、文件系统丢写或断电。

switch、update（含控制台更新）及 repair 的检查点准备等待使用
[`wait_for_checkpoint`](../../lkit-cli/tests/install_fixture_e2e/support/checkpoints.rs)，
时限为 120 秒，涵盖排队、debug 二进制校验与下载、保护备份压缩及健康检查。
操作在到达标记前进入终态时立即失败；超时和提前终结均直接读取持久化操作及事务记录，
输出诊断，不依赖 CLI 响应。准备耗时通过事件时间线与检查点标记定位，故障注入后的恢复
期限独立保留，检查点到达后的 gate 暂停时限也单独计算。

| 操作 | 返回错误的边界 | 强杀后恢复的边界 |
| --- | --- | --- |
| 首次安装 | 发布前、release 发布后、启动服务前 | 发布前、release 发布后、激活后、启动服务前、state 写入后、结果保存前、待网络确认 |
| 版本切换 | 发布前、启动服务前、state 写入前 | 服务停止后、发布前、激活后、state 写入后、结果保存前；有／无保护备份 |

断言覆盖原状态与 current、原有数据、服务运行状态、操作和事务身份、事务终态，以及重启后
不重复执行已完成操作。返回错误必须到达指定 `.failed` 标记，不能把其他提前失败算作通过。
提交前恢复旧现场，提交后补齐回执；已经停止但尚未激活的切换保持其独立恢复语义。

真实磁盘写入错误、服务命令中途强杀、更多操作与后端的交叉矩阵、虚拟机断电仍需专项覆盖。
新增故障应优先绑定具体恢复不变量，不通过单纯扩大超时或自动重试使测试变绿。
