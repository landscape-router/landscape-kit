# daemon 网络确认与恢复

## 职责与支持范围

lkit daemon 统一管理首次网络接管、reinit 和备份 restore 的确认期限、主机重启检测与
自动回滚。systemd、OpenRC 和 SysVinit 负责托管 daemon；宿主服务的查询、屏蔽、停止
和恢复由对应后端执行。事务不创建专属 systemd timer 或回滚 service。

所有新 restore 都需网络确认，因为备份可以改变管理地址与网络配置。restore 使用
schema v14 的独立确认记录，不重新接管宿主网络服务；首次接管和 reinit 使用
`network_takeover` 中的网络计划与宿主服务快照。两类记录共用确认期限和恢复决策。

网络接管要求 daemon 已注册、启用且可用。停止宿主网络服务之前，事务必须持久化
完整恢复依据。NetworkManager 活动连接的 UUID、接口永久身份、地址族与默认网关一并保存。无法读取服务状态、无法保证恢复或存在不受支持的活动网络管理器时，
接管在修改宿主网络之前失败。

服务状态包括运行状态和开机启动状态：systemd 保存 enable/mask 状态，OpenRC 保存
runlevel 成员关系，SysVinit 保存启动链接及顺序。回滚恢复原状态，不启动原本停止的
服务，不启用原本禁用的服务。恢复操作必须可重试。

## 确认与恢复

用户通过 `lkit network confirm` 显式确认应用后的网络可达，CLI 将安装根及事务 ID 提交给 daemon，
不传递任意命令行、会话环境或终端设备。手工回滚使用同一持久化操作通道，
前端退出不终止执行；结果通过 `operation status/list` 查询。首次接管和 reinit 复核
网卡身份、网络计划和 Landscape 健康；restore 复核 pending state 的安装根、事务及
版本身份、执行后端、活动二进制、PID 和健康。用户从应用后的网络验证访问，本机健康
检查不能替代这项确认。校验通过后进入 `finalizing`，表示确认决定已持久化；中断恢复
继续提交，即使期限已到或主机已重启也不撤销决定。`finalizing` 不接受手动回滚。

确认开始时以及完成所有校验和确认前网络操作后、持久化 `finalizing` 之前，均读取
当前时间和主机启动标识。只有 `now < confirmation_deadline` 且启动标识匹配才能
接受确认；等于截止时刻即超时。校验期间跨越期限时返回超时错误，保留待确认事务
供 daemon 或显式回滚处理，不延长期限、不写入已提交安装状态。读取启动标识失败
时拒绝确认。确认与回滚在同一安装锁下串行，`finalizing` 持久化后恢复只续做提交。

首次接管、reinit 和 restore 的 `awaiting_network_confirmation` 均保持原确认期限。
restore 在目标启动并通过健康检查后开始确认窗口，旧已提交 state 保持不变；接受确认
后才提交目标 state。期限到达后 daemon 进入 `rolling_back`，daemon 进程重启不延长
期限。事务保存主机启动标识，标识变化表示主机重启，daemon 立即回滚尚未确认的目标。

`rolling_back` 中途失败时保留恢复依据和非终态，记录错误并在后续恢复周期重试。
NetworkManager 原连接恢复并满足其地址族、默认网关要求后才标记 `rolled_back`；
连接已开始激活但 DHCP 尚未完成时只检查进展，不重复激活重置租约获取。
所有物理接口身份验证通过后，单个连接激活失败不阻止尝试恢复其他原连接；
已经恢复的连接在后续周期不重复激活，任一连接尚未恢复时事务仍保持 `rolling_back`。
缺少连接快照的旧事务保持服务级恢复兼容性并提示人工核验。已经提交的事务不再参与超时回滚。

确认、回滚与安装共享安装锁。恢复检查不得因无关委托请求而无限期排队；正在修改
同一安装现场的操作持锁期间，恢复等待锁释放后重新读取事务，再判断应执行的动作。

## 启动与生命周期

Landscape 的启动入口执行 lkit 恢复检查。有跨主机启动遗留的未确认接管、reinit、
restore 或正在执行的回滚时，目标配置启动被阻断；reinit 和 restore 恢复原数据后可
启动原配置进行恢复健康校验。
恢复失败不能放行未确认的目标配置抢占宿主网络。
同次主机启动中，未到确认期限的安装和网络校验允许启动目标 Landscape，以完成
接管验证。待确认事务已经到期时，即使主机未重启也阻止目标配置再次启动。事务
损坏、版本未知或启动标识无法读取时拒绝启动并报告原因，不能当作没有待恢复事务。
启动检查只读取恢复依据，不等待安装锁或自行执行回滚，避免与持锁启动服务的 daemon 执行线程
死锁。reinit 和 restore 的恢复放行凭据 `transactions/<id>/restored-boot-id` 仅针对
当前事务、当前主机启动及已经恢复的原配置，不能供待确认的目标配置复用。

restore 在停止前记录原 data 的设备号和 inode。回滚只将身份匹配的真实目录视为原
数据，或使用有效保护 `.lkb` 重建原配置，完成后才写入启动放行凭据。缺少原数据和
可用保护备份时保持阻断。每次回滚重试在修改服务或数据前撤销旧凭据并同步目录，
重新恢复原配置后才允许启动，避免同次主机启动中的旧凭据放行尚未恢复的数据。

启动顺序不等同于恢复完成。三个后端的启动入口均执行恢复检查，不依赖 init 系统
对“服务已启动”的不同定义。已确认并正常运行的 Landscape 不因 daemon 的升级或
短暂重启而被停止。

daemon 运行状态与恢复能力需要分别验证：仅有存活 PID 不代表支持当前事务格式。
启动接管、restore 或服务定义迁移前，运行中的 daemon 必须声明对应恢复能力；
restore 要求 `restore-v2.pid` 且 PID 与实际 daemon 一致。能力缺失时先完成 lkit 升级
和 daemon 重启，不先修改网络或写入它不能恢复的事务。

三个 init 后端均通过 `lkit daemon --supervise` 运行统一监管进程，由它启动实际 daemon。
实际 daemon 意外退出或启动失败时，重试间隔依次为 **1s、3s、5s、10s**，随后一直
以 10s 间隔重试，不设次数上限。连续运行至少 5 分钟后，下一次失败从 1s 开始。
显式重启创建新的监管进程并重置退避。主动停止或卸载会通知监管进程退出，取消等待中的
重试；有运行中的 daemon 时转发 SIGTERM 并等待它结束当前恢复周期，不再拉起。

监管进程和实际 daemon 各自持有实例锁，避免重复启动。init 的 MainPID／`/run/lkit.pid`
表示监管进程，地盘中的 `run/lkit.pid` 表示实际 daemon，能力标识绑定后者。
systemd 对监管进程自身的退出使用 10 秒重启间隔并关闭启动次数限制；OpenRC／SysVinit
托管长期运行的监管进程。监管进程自身被强杀、主机故障不属于 daemon 子进程退避保证。

自动恢复需要实际 daemon 运行。退避期间事务和期限保持不变；daemon 恢复后立即按
持久化期限与启动标识处理。启动检查独立阻止危险配置再次启动。升级已有部署后执行
`lkit self install` 刷新 daemon 服务入口，使其启用统一监管。

存在未完成事务时，`lkit self remove` 拒绝移除恢复责任主体。daemon 升级和重启必须
保留事务、确认期限及恢复数据。存在未完成事务时禁止降级到不能读取该事务格式的版本。旧版 systemd 恢复事务仍可读取和完成，清理旧恢复
unit 必须在事务得到处理后进行。事务读取支持 schema v1 至 v14；旧 v9 restore 保持
其原有恢复语义，不补造确认窗口或原数据身份。

## 网络现场与恢复边界

服务状态恢复和网络现场恢复分别验证。回滚首先停止未确认的 Landscape，恢复接管前
配置和宿主服务，再清理未提交安装；reinit 恢复原 Landscape 配置与服务状态。
reinit 在修改前保存 Landscape 的实际运行状态和开机启动状态。回滚首先停止目标
进程并恢复旧数据和注册；原本运行时启动旧配置并通过健康检查，原本停止时保持停止、
验证目标进程已经退出，不执行要求进程在线的健康检查。两种情况均恢复原启用状态，
成功 reinit 也不隐式改变原开机启动设置。允许无保护备份不改变这些恢复要求。
原服务停止时，回滚不承诺恢复由 Landscape 提供的网络连通性。

restore 回滚恢复原 release、current、data、服务注册及启用／运行状态和保存的 DNS
文件，不回滚宿主网络管理器接管状态。原本运行的服务通过完整健康检查后才完成回滚；
原本停止的服务保持停止。原 data 丢失时保护 `.lkb` 只提供配置级恢复，不包含 SQLite
数据库字节、日志或 API token。

宿主服务依据其原有配置重建网络；DHCP 地址由原客户端重新获取，不承诺获得同一租约。
不修改用户未选择的接口配置，不把宿主服务恢复成功等同于外部网络必然可达。

## 验收

单元测试使用临时目录、假服务管理器及可注入的时间与主机启动标识，覆盖期限边界、
进程重启、主机重启、确认竞争、提交续做、回滚重试和旧事务兼容。服务状态恢复覆盖
原本停止、禁用、不同 runlevel 与不同启动顺序等状态。

真实服务操作、开机启动屏障和网络恢复由 CI 的 fixture、容器或虚拟机验证，分别覆盖
systemd、OpenRC 和 SysVinit。普通开发过程不在宿主执行这些系统级测试。

Landscape 服务定义须包含 `lkit network startup-check`，该要求同时适用于 systemd、
OpenRC 和 SysVinit。缺少启动检查时，reinit 与 restore 在创建事务、保护备份或修改
现场前拒绝执行，提示运行 [`lkit repair service`](../commands/repair.md#服务定义修复)。
修复成功后重新确认并执行操作；修复失败不放宽启动检查，`--yes` 与
`--allow-no-backup` 也不能跳过该检查。

## 恢复通道配置

flare 独立读取 `config.toml` 的 `[flare]` 段。仓库配置缺失或仓库字段不合法不影响
有效 PSK 的读取，daemon 重启保留该 PSK，不因无关配置重新生成恢复密钥。
